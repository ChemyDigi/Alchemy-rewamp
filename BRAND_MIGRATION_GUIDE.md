# Brand/Client System Migration Guide

## Overview

This guide explains the complete migration of the Brand/Client system from local JSON files to a fully dynamic Firebase Firestore + Cloudinary setup.

## What's Changed

### ✅ Removed
- ❌ Local JSON files (`data/brand.json`, `data/gallery.json`)
- ❌ Hardcoded arrays in components
- ❌ Firebase Storage (NO Firebase Storage is used)
- ❌ Local image references

### ✅ Added
- ✅ Firebase Firestore for data persistence
- ✅ Cloudinary for image uploads and storage
- ✅ Full admin CRUD interface
- ✅ Dynamic routing with static generation
- ✅ Loading, error, and empty states
- ✅ TypeScript interfaces for type safety

## Database Structure

### Firestore Collection: `brands`

Each document follows this structure:

```typescript
{
  id: string                    // Auto-generated by Firestore
  slug: string                  // URL slug (unique)
  brandName: string             // Display name
  shortTitle: string            // Short description
  heroImage: string             // Cloudinary URL (brands/hero/)
  logoImage: string             // Cloudinary URL (brands/logo/)
  thumbnailImage: string        // Cloudinary URL (brands/thumbnail/)
  bornYear: string              // Year brand was founded
  introduction: string          // Long description
  galleryTitle: string          // Gallery section title
  
  details: {
    brandName: string           // Detail name (can differ from main)
    timeFrame: string           // "Present" or "2020-Present"
    role: string                // "Digital Marketing", "Creative Director", etc.
    industry?: string           // Optional industry
    services?: string[]         // Optional services array
  }
  
  gallery: [                    // Gallery items array
    {
      id: number                // Unique ID (timestamp)
      src: string               // Cloudinary URL (brands/gallery/)
      className: string         // Grid class: "col-span-1 row-span-1" | "col-span-1 row-span-2" | "col-span-2 row-span-1" | "col-span-2 row-span-2"
      type: "image" | "empty"   // "image" or placeholder
      alt: string               // Alt text
      order: number             // Position in gallery
    }
  ]
  
  featured: boolean             // Show first in carousel
  isPublished: boolean          // Show on frontend
  
  createdAt: Timestamp          // Auto-set on creation
  updatedAt: Timestamp          // Auto-updated on changes
}
```

## Setup Instructions

### 1. Environment Variables

Add these to your `.env.local`:

```env
# Firebase
NEXT_PUBLIC_FIREBASE_API_KEY=...
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=...
NEXT_PUBLIC_FIREBASE_PROJECT_ID=...
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=...
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=...
NEXT_PUBLIC_FIREBASE_APP_ID=...

# Cloudinary
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=...
NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET=...
```

### 2. Firestore Setup

1. Go to Firebase Console → Firestore Database
2. Create a collection named `brands`
3. No need to pre-create documents (done via admin panel)

### 3. Cloudinary Setup

1. Create unsigned upload preset in Cloudinary dashboard
2. Set to allow uploads to:
   - `brands/hero/`
   - `brands/logo/`
   - `brands/thumbnail/`
   - `brands/gallery/`

## API Functions

All functions are in `lib/firestore-brands.ts`:

### Read Operations

```typescript
// Get all published brands
const brands = await getPublishedBrands();

// Get featured brands only
const featured = await getPublishedBrands(true);

// Get all brands (admin)
const allBrands = await getAllBrands();

// Get single brand by ID
const brand = await getBrandById("brandId");

// Get brand by slug
const brand = await getBrandBySlug("tommee-tippee");
```

### Write Operations

```typescript
// Create new brand
const newId = await createBrand(brandData);

// Update brand
await updateBrand(brandId, partialBrandData);

// Delete brand
await deleteBrand(brandId);

// Check if slug exists
const exists = await isSlugExists("slug");
```

## Image Upload Flow

### Frontend → Cloudinary
1. User selects image in admin form
2. `uploadToCloudinary(file, folder)` called
3. Image sent to Cloudinary
4. Secure URL returned
5. URL stored in form state

### On Brand Save
1. All Cloudinary URLs already set
2. Firestore document created/updated
3. URLs stored in document
4. Frontend fetches from Firestore
5. Images display from Cloudinary

### Key Points
- ✅ All uploads are unsigned (safe)
- ✅ No backend required
- ✅ No Firebase Storage used
- ✅ Images organized in folders
- ✅ Direct Cloudinary URLs stored

## Migrations from Old System

### From JSON to Firestore

If migrating existing brands:

```typescript
// Example data from old JSON
const oldBrand = {
  id: "tommee-tippee",
  slug: "tommee-tippee",
  heroImage: "/images/brand-main.png",
  // ...
};

// 1. Upload images to Cloudinary separately
const heroUrl = await uploadToCloudinary(heroImageFile, "brands/hero");

// 2. Create object with Cloudinary URLs
const newBrand = {
  ...oldBrand,
  heroImage: heroUrl,
  // ... upload other images
  featured: true,
  isPublished: true,
};

// 3. Save to Firestore
await createBrand(newBrand);
```

## Troubleshooting

### Images Not Uploading
- Check Cloudinary credentials in `.env.local`
- Verify upload preset exists and is unsigned
- Check browser console for errors
- Verify CORS settings in Cloudinary

### Firestore Data Not Loading
- Check Firebase credentials
- Verify collection name is "brands"
- Check Firestore security rules allow reads
- Check browser Network tab in DevTools

### Slug Already Exists Error
- Slug must be unique
- Check existing brands in Firestore
- Try different slug

### Images Not Displaying
- Check image URLs in Firestore
- Verify Cloudinary URLs are valid
- Check CORS headers
- Verify image files exist in Cloudinary
